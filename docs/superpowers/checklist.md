# Superpowers workflow

## Brainstorming

- [x] Explore context: new project, no existing application code.
- [x] Identify scope: full parity is multiple independent delivery phases.
- [x] Confirm phone platforms: Android and iPhone.
- [x] Confirm audience: other people as well as the user.
- [x] Record extension request; distinguish proposals from verified missing features.
- [ ] Offer visual companion only when a concrete visual comparison needs it.
- [x] Present phased implementation as recommended, with UI-only and all-at-once alternatives recorded in the proposal. Product-owner approval remains pending.
- [ ] Receive design approval.
- [ ] Write and commit the approved design.
- [ ] Self-review for ambiguity, contradictions, placeholders, and scope.
- [ ] Obtain review of the written specification.
- [ ] Invoke writing-plans and produce the implementation plan.

## Implementation and verification, after approval

- [ ] Define slice acceptance checks before app code.
- [ ] Use meaningful tests with red/green verification where appropriate.
- [ ] Verify functional flows and persistence, not only screenshots.
- [ ] Compare observed reference screens and feature coverage.
- [ ] Run fresh checks before completion claims.
- [ ] Record gaps and update `STATUS.md`.
